P1Initial product build

Build a responsive web application called "Custom Order Desk" for small Indian businesses that handle customised customer orders through WhatsApp and Instagram, particularly home bakers and boutique sellers.

The product should help business owners manage customer-specific order requirements, advance payments, pending balances and promised delivery dates.

DESIGN:
- Clean, minimal, premium SaaS dashboard.
- White/light background with subtle green accents.
- Professional typography and clear visual hierarchy.
- Desktop-first but responsive on mobile.
- Currency in INR.

CORE SCREENS:
1. DASHBOARD
- Show total active orders, deliveries due today, pending balances and overdue orders.
- Display recent orders in a searchable table.
- Add filters for order status and delivery date.
- Provide a prominent "Add New Order" action.

2. ADD / EDIT ORDER
Fields: customer name and phone number; product name; customisation requirements; reference image URL (optional); total order amount; advance payment received; delivery date and time; additional notes; order status.
Automatically calculate remaining balance.

3. FULFILMENT BOARD
Display orders grouped by Confirmed, In Preparation, Ready, Delivered. Allow users to update order status.

FUNCTIONAL REQUIREMENTS:
- Add, edit and delete orders.
- Search and filter orders.
- Update payment status and fulfilment status.
- Calculate outstanding balances automatically.
- Highlight overdue and upcoming orders.
- Persist data using local storage or an appropriate simple backend.

Populate the app with 6 realistic sample orders for an Indian home bakery.

P2Functional refinement

Review the existing Custom Order Desk application and make the following improvements in this single build. Preserve the current visual design, layout, colour palette, navigation and existing working features. Do not rebuild the app from scratch or introduce unnecessary new features.

1. Complete Add/Edit Order functionality
- Ensure the Add New Order button opens a working form.
- Include customer name, phone number, product name, customisation requirements, reference image URL (optional), total order amount, advance payment, delivery date, delivery time and additional notes.
- Allow existing orders to be edited.
- Validate required fields and prevent negative or invalid payment amounts.
- Ensure the advance payment cannot exceed the total order amount.
- Calculate the remaining balance automatically.

2. Improve payment tracking
- Allow the owner to record additional payments against an existing order.
- Update the outstanding balance immediately after a payment is recorded.
- Automatically show Paid, Partially Paid or Unpaid based on the remaining balance.
- Keep payment status separate from fulfilment status.

3. Ensure order management works
- Add, edit and delete orders. Ask for confirmation before deleting.
- Allow orders to move through Confirmed → In Preparation → Ready → Delivered, and back to a previous stage if needed.
- Ensure changes are reflected immediately across the dashboard, recent orders and fulfilment board.

4. Correct dashboard calculations (dynamic, from actual order data)
- Active Orders: all orders not yet delivered.
- Deliveries Due Today: undelivered orders scheduled for today's date.
- Pending Balances: sum of outstanding balances across relevant orders.
- Overdue Orders: undelivered orders with a delivery date earlier than today.
Delivered orders must not count as active or overdue. Use the current date dynamically rather than hardcoded dates.

5. Improve search and filters
- Search by customer name, phone number and product name.
- Filter by fulfilment status and delivery date.
- Ensure filters and search work together; provide a clear reset option.

6. Make customisation details central
Customisation requirements are the key reason this product exists. Make them easy to access and read when viewing an order. Do not hide important details such as flavour, design, size, colour, reference instructions or customer preferences behind truncated text.

7. Ensure data persistence
- Save orders so they remain available after refreshing or reopening the app (local storage if no backend).
- Ensure sample orders and newly created orders follow the same data structure.
- Avoid losing existing sample orders or user-created data during normal app usage.

8. Fix responsive design
- Make the app fully usable on mobile, tablet and desktop.
- Fix the horizontal overflow and scrolling issues in the recent orders table; on smaller screens use readable stacked order cards or another suitable layout.
- Ensure all buttons, forms, navigation and order details remain accessible on mobile.

9. Final functionality check. Before finishing, test: (1) add a new order and verify it appears on the dashboard and fulfilment board; (2) edit it and verify the changes everywhere; (3) record an additional payment and verify the balance; (4) move the order through all fulfilment stages; (5) verify dashboard counts and overdue indicators; (6) search and filter; (7) refresh and verify data persists.
